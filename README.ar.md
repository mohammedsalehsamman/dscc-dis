# مشروع DSCC-DIS — منظومة متكاملة (SOAP + RMI)

> [English version](README.md)

الجامعة العربية الدولية — هندسة المعلوماتية والاتصالات

المشروع يحقق المطلوب في نص المشروع (نظام موظفين بـ SOAP، ونظام مكتبة بـ RMI)، ويضيف فوقه:
- **ربط فعلي بين النظامين:** سيرفر RMI يتحقق من الموظفين عن طريق استدعاء خدمات SOAP.
- **دخول موحد بصلاحيات:** يسجّل المستخدم دخوله مرة واحدة.
- **تخزين دائم في SQLite:** البيانات تبقى بعد إعادة تشغيل السيرفر.
- **تحديثات لحظية:** RMI Callbacks في المكتبة، و SOAP Polling في الموظفين.
- **واجهات حديثة:** FlatLaf مع وضعين فاتح وداكن.
- **لوحات إحصاء وتقارير:** قابلة للتصدير إلى CSV أو PDF.

---

## 1. بنية المجلد

```
dscc-dis/
├── dscc-common/         مكتبة مشتركة: مكونات الواجهة، الإعدادات، تشفير كلمات المرور، SOAP header handler
├── employee-soap/       سيرفر SOAP + عملاء الموظفين
├── library-rmi/         سيرفر RMI + عملاء المكتبة + عميل SOAP مولَّد بـ wsimport
├── dscc-portal/         البوابة الموحدة (تسجيل دخول واحد للنظامين)
├── pom.xml              مشروع Maven الأب (المكتبات الخارجية تُحمَّل تلقائياً من Maven Central)
├── mvnw / mvnw.cmd      Maven Wrapper: لا حاجة لتثبيت Maven
├── config.properties    الإعدادات (عناوين السيرفرات، مدة الإعارة، الغرامة...)
├── build-all.bat / .sh  بناء المشاريع الأربعة
├── run.bat / run.sh     تشغيل أي جزء
└── start-all.bat / .sh  تشغيل السيرفرين ثم البوابة بنقرة واحدة
```

كل وحدة فيها الكود في `src/main/java` والاختبارات في `src/test/java`.
المكتبات المستخدمة: JAX-WS RI 2.3.7 (حُذف من JDK منذ الإصدار 11)، FlatLaf 3.5.4، sqlite-jdbc، JUnit 5.

**المتطلبات:** JDK 17 أو أحدث، و NetBeans أو IntelliJ (اختياري).

## 2. التشغيل

### الطريقة الأسرع
نقر مزدوج على **`start-all.bat`**، فيقوم بما يلي:
1. يبني المشروع إذا لم يكن مبنياً (أول مرة يحمّل Maven والمكتبات من الإنترنت).
2. يشغّل سيرفر SOAP.
3. يشغّل سيرفر RMI.
4. يفتح البوابة.

كل سيرفر يفتح نافذة **Server Monitor** تعرض:
- مدة التشغيل.
- عدد الطلبات.
- عدد العملاء المتصلين.
- سجلاً حياً لكل عملية.

### من سطر الأوامر
```bash
mvnw.cmd verify          # بناء + تشغيل الاختبارات   (لينكس/ماك: ./mvnw verify)
run.bat soap-server      # 1. سيرفر SOAP
run.bat rmi-server       # 2. سيرفر RMI
run.bat portal           # 3. البوابة
```

### من NetBeans أو IntelliJ
1. افتح المجلد الرئيسي `dscc-dis` كمشروع Maven، فتظهر الوحدات الأربع تلقائياً.
2. **سيرفر SOAP:** شغّل الكلاس `employee.server.EmployeePublisher` (مجلد العمل: `employee-soap`).
3. **سيرفر RMI:** شغّل الكلاس `library.server.LibraryServer` (مجلد العمل: `library-rmi`).
4. **البوابة:** شغّل الكلاس `dscc.portal.PortalApp`.
5. **العملاء المستقلون** يعملون بـ Run File (Shift+F6) على الكلاس المطلوب، وهي مذكورة في الجدول أدناه.

> **الترتيب مهم:** سيرفر SOAP أولاً، لأن سيرفر RMI يعتمد عليه للتحقق من الموظفين.

### كل الواجهات المتاحة

| الأمر | الكلاس | الوصف |
|---|---|---|
| `run.bat portal` | `dscc.portal.PortalApp` | **البوابة الموحدة** (الأفضل للعرض) |
| `run.bat soap-client` | `employee.client.ui.EmployeeClientApp` | تطبيق الموظفين الكامل |
| `run.bat rmi-client` | `library.client.ui.LibraryClientApp` | تطبيق المكتبة الكامل (موظف / طالب / زائر) |
| `run.bat soap-simple` | `employee.client.EmployeeClientGUI` | العميل البسيط للعمليات الأربع المطلوبة |
| `run.bat rmi-simple` | `library.client.LibraryClientGUI` | العميل البسيط لعمليات المكتبة المطلوبة |

### حسابات تجريبية

| الدور | الدخول | ماذا يرى |
|---|---|---|
| ADMIN | `admin` / `admin123` | كل شيء: الموظفون، الرواتب، الحسابات، المكتبة، التقارير |
| LIBRARIAN | `librarian` / `lib123` (أو `maya`) | المكتبة كاملة + Dashboard + تقارير المكتبة |
| EMPLOYEE | `employee` / `emp123` | ملفه الشخصي + فهرس الكتب للقراءة فقط |
| STUDENT | `S1001` … `S1006` / PIN `1234` | إعاراته، حجوزاته، غراماته، والحجز من الفهرس |

### التشغيل على عدة أجهزة
- **على جهاز السيرفر:**
  - عدّل `soap.url` في `config.properties` إذا كان سيرفر SOAP على جهاز آخر.
  - شغّل سيرفر RMI مع تمرير IP جهازه: `run.bat rmi-server 192.168.1.10`
- **على جهاز العميل:** من شاشة الدخول اضغط **⚙ Servers…** واكتب عناوين السيرفرات، ثم اضغط Test connection.
- **جدار الحماية:** اسمح لـ Java بالمنافذ 8080 (SOAP) و 1099 (RMI). التحديث اللحظي يحتاج أيضاً اتصالاً من السيرفر إلى العميل.

## 3. المعمارية

```
            ┌──────────────────────── dscc-portal / العملاء ────────────────────────┐
            │  Login ─► SOAP AuthService.login ─► token                             │
            │  الموظفون: SOAP + token في SOAP Header      المكتبة: RMI + نفس الـ token │
            └──────────────┬───────────────────────────────────────┬─────────────────┘
                     SOAP/HTTP :8080                         RMI :1099   ▲ callbacks (push)
                           ▼                                        ▼   │
     ┌──────────── employee-soap ───────────┐       ┌──────────── library-rmi ────────────┐
     │ /AuthService      login, tokens,     │◄──────│ EmployeeVerifier (عميل wsimport)      │
     │                   حسابات المستخدمين   │ SOAP  │   validateToken + getEmployee         │
     │ /EmployeeService  CRUD + إحصاءات       │       │ LibraryServiceImpl + EventBus          │
     │ AuthServerHandler يقرأ token من Header │       │ فحص التأخير كل دقيقة                    │
     │ SQLite: employees.db                 │       │ SQLite: library.db                     │
     └──────────────────────────────────────┘       └────────────────────────────────────────┘
```

### نظام الموظفين (SOAP / JAX-WS)
- **العمليات المطلوبة بتوقيعها الأصلي:**
  - `addEmployee(Employee)` و `getEmployee(int)` و `updateEmployee(Employee)` و `deleteEmployee(int)`.
  - كل منها يعيد Success/Failure أو كائن Employee.
- **عمليات إضافية:**
  - `listEmployees`
  - `searchEmployees`
  - `getDepartments`
  - `getStatistics` (يحسب بـ SQL GROUP BY)
  - `applyRaise` (زيادة رواتب قسم)
  - `getActivitySince` (للتحديث اللحظي)
- **خدمة ثانية `AuthService`:**
  - `login` و `logout` و `validateToken` و `changePassword`.
  - إدارة الحسابات: `createUser` و `listUsers` و `deleteUser` و `resetPassword`.
- **الأمان:**
  - **المصادقة:** التوكن يُرسل في **SOAP Header** (`<auth:Token>`):
    - في العميل: `TokenHeaderHandler` يضيفه لكل طلب.
    - في السيرفر: `AuthServerHandler` يقرأه، ويرفض الطلب بـ **SOAP Fault** إن كان مفقوداً أو منتهياً.
  - **الفائدة:** لم نغيّر توقيع العمليات المطلوبة.
  - **الصلاحيات (Authorization):** داخل الخدمة. الإضافة والتعديل والحذف للـ ADMIN فقط، والموظف يقرأ سجله فقط.
  - **كلمات المرور:** تُخزَّن PBKDF2-HMAC-SHA256 مع salt عشوائي، والـ hash القديم (SHA-256) يُرقّى تلقائياً عند أول دخول.

### نظام المكتبة (Java RMI)
- **الدوال المطلوبة كما هي:**
  - `addBook(id, title, author)`
  - `searchBook(title)` يعيد `"Book not found"` إن لم يجد.
  - `viewAllBooks()` يعيد `List<String>`.
  - `viewIssuedHistory()`
- **كلاس `Book`:** كما طُلب (constructors، getters/setters، toString)، مع حقول إضافية: الفئة، ISBN، السنة، عدد النسخ.
- **"بنية بيانات منفصلة لسجلات الإعارة":** جدول `loans` مستقل عن جدول `books`.
- **إضافات:**
  - **الطلاب:** تسجيل الطلاب، والدخول برقم الطالب و PIN.
  - **الإعارة:** تاريخ استحقاق بعد 14 يوماً، وتجديد مرتين كحد أقصى.
  - **الغرامة:** 500 عن كل يوم تأخير.
  - **منع الإعارة:** لا تُعار كتب لطالب لديه تأخير أو غرامة غير مدفوعة.
  - **الحجز بطابور انتظار:** عند إرجاع كتاب محجوز تُحجز النسخة لأول طالب في الطابور (READY).
  - **الإحصاءات.**
- **التحديث اللحظي (RMI Callbacks):**
  - العميل يصدّر كائناً يطبق `LibraryCallback` ويسجّله في السيرفر.
  - السيرفر يستدعيه عند كل تغيير (`EventBus`)، فيتحدث كل عميل مفتوح فوراً مع إشعار منبثق.
  - إذا انقطع عميل يُحذف تلقائياً.

### الربط بين النظامين
- **عميل SOAP مولَّد:** سيرفر RMI لا يملك حسابات موظفين. فيه عميل SOAP **مولَّد من WSDL بأداة `wsimport`** في الحزمة `library.integration.soap`، ولا يشارك أي كود Java مع مشروع SOAP، فالعقد (WSDL) يكفي.
- **التحقق من الموظف:** عند كل عملية موظفين (إضافة كتاب، إعارة، إرجاع...) يستدعي `EmployeeVerifier`:
  1. `AuthService.validateToken`: من صاحب التوكن؟ وهل دوره LIBRARIAN أو ADMIN؟
  2. `EmployeeService.getEmployee`: هل سجل الموظف ما زال موجوداً؟
- **التخزين المؤقت:** النتيجة تُحفظ 60 ثانية.
- **اسم الموظف في القرض:** يُخزَّن في كل قرض (`issued_by_employee`).
- **تقرير "Loans by employee" في البوابة:** يجمع عدد الإعارات من RMI مع أسماء وأقسام الموظفين من SOAP.
- **إعادة توليد عميل SOAP:** `mvnw.cmd -pl library-rmi -am -Pwsimport compile` (والسيرفر SOAP يعمل).

### ميزات الواجهات
- **الجداول:** بحث فوري، فرز بالضغط على العنوان، فلترة (قسم أو فئة أو متاح فقط)، تلوين الصفوف (المتأخر أحمر، والغرامة غير المدفوعة برتقالي).
- **النماذج:** تحقق فوري، والحقل الخاطئ يتلون بالأحمر أثناء الكتابة.
- **الإشعارات:** منبثقة (Toast)، وتأكيد قبل الحذف.
- **اختصارات لوحة المفاتيح:**
  - Ctrl+N إضافة
  - Ctrl+F بحث
  - F5 تحديث
  - Del حذف
- **البيانات:**
  - تصدير CSV (يُفتح في Excel مع دعم العربية).
  - طباعة أو PDF (اختر "Microsoft Print to PDF").
- **الإحصاءات:** لوحات ورسوم بيانية (Java2D، بدون مكتبات).
- **المظهر:** وضع فاتح أو داكن يُحفظ للمرة القادمة.
- **شريط الحالة:** يعرض حالة السيرفرين (أخضر أو أحمر) ويُفحص كل 5 ثوانٍ.

### تنظيم كود سيرفر المكتبة
`LibraryServiceImpl` هو واجهة RMI فقط: يتحقق من هوية المتصل (موظف عبر SOAP أو طالب بجلسته) ثم يسلّم العمل لخدمة متخصصة:
`CatalogService` (الكتب)، `StudentService` (الطلاب وجلساتهم)، `LoanService` (الإعارة والإرجاع والغرامات)، `ReservationService` (الحجز وطابور الانتظار).

## 4. الاختبارات
`mvnw.cmd verify` يشغّل 42 اختباراً (وتعمل تلقائياً على GitHub Actions مع كل push):
- **SOAP من طرف لطرف:** نشر الخدمات الحقيقية مع الـ Handler على منفذ حر، واختبار الدخول والتوكن والصلاحيات.
- **RMI ذهاباً وإياباً:** Registry و lookup واستدعاءات بعيدة، و callback يستدعيه السيرفر عبر RMI.
- **قواعد المكتبة:** الغرامة، حد التجديد، منع الإعارة مع غرامة، طابور الحجز، عدد النسخ.
- **تشفير كلمات المرور** وترقية الـ hash القديم.
