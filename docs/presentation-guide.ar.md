# دليل العرض والمناقشة — DSCC-DIS

> [العودة إلى README](../README.ar.md)

## 1. سيناريو العرض المقترح (حوالي 10 دقائق)

1. **التشغيل:** شغّل `start-all.bat` واعرض نافذتَي Server Monitor.
2. **SOAP:**
   - افتح `http://localhost:8080/EmployeeService?wsdl` في المتصفح.
   - شغّل `run.bat soap-simple` ونفّذ العمليات الأربع المطلوبة: Add ثم Get ثم Update ثم Delete.
3. **البوابة بحساب `admin`:**
   - Dashboard فيه بيانات من السيرفرين معاً.
   - Employees: أضف موظفاً، وجرّب البحث والفلترة.
   - Payroll: نفّذ زيادة 5% لقسم IT وراقب الرسم يتغير.
4. **التحديث اللحظي (أهم نقطة):**
   - افتح نافذة ثانية: `run.bat rmi-client` بحساب `librarian`.
   - في البوابة: Loans ثم Issue book.
   - النتيجة: النافذة الثانية تتحدث فوراً مع إشعار، والسيرفر هو من دفع الحدث.
5. **الربط والصلاحيات:**
   - سجّل الدخول بـ `employee/emp123`: يرى ملفه فقط، ولا يستطيع إدارة المكتبة.
   - السبب: سيرفر RMI سأل SOAP فوجد دوره EMPLOYEE.
6. **الحجز:**
   - طالب `S1004` يحجز كتاباً كل نسخه معارة (الأحمر في الفهرس).
   - أمين المكتبة يرجع النسخة.
   - النتيجة: الطالب يصله إشعار "جاهز للاستلام".
7. **الغرامة:**
   - الطالب `S1002` لديه كتاب متأخر بالأحمر.
   - عند إرجاعه تُحسب الغرامة.
   - تظهر في Reports ثم Unpaid fines.
8. **التقارير:** صدّر تقريراً إلى CSV واطبعه PDF.
9. **الاستمرارية:** أغلق سيرفر RMI وأعد تشغيله، والبيانات باقية (SQLite).

> **لإعادة البيانات التجريبية من الصفر:** احذف `employee-soap\data` و `library-rmi\data` ثم شغّل السيرفرين.

## 2. أسئلة متوقعة في المناقشة

- **ما الفرق بين SOAP و RMI؟**
  - **SOAP:** رسائل XML فوق HTTP موصوفة بـ WSDL، ويمكن لأي لغة استدعاؤها. أثبتنا ذلك بتوليد عميل من WSDL فقط.
  - **RMI:** خاص بـ Java، يستدعي دوال كائن على JVM أخرى عبر Stub و Serialization، وأسرع ويدعم الاستدعاء العكسي (callbacks).
- **كيف يعمل التحديث اللحظي في كل نظام؟**
  - **RMI:** يدعم **Push**. العميل نفسه كائن بعيد (`LibraryCallback`) والسيرفر يستدعيه.
  - **SOAP:** طلب ورد فقط، فاستخدمنا **Polling**: العميل يسأل كل 3 ثوانٍ `getActivitySince(lastId)`.
- **لماذا وضعنا التوكن في SOAP Header وليس كمعامل؟**
  - للحفاظ على توقيع العمليات المطلوبة.
  - لفصل المصادقة (Handler) عن منطق العمل، وهذا هو الأسلوب القياسي في WS-Security.
- **ما هو SOAP Handler؟** كود يعترض الرسالة قبل وصولها للخدمة أو بعدها. استخدمناه لقراءة التوكن وإضافته.
- **لماذا الدوال `synchronized` أو `synchronized (db)`؟** لأن RMI والـ HTTP server يخدمان كل عميل بخيط (Thread) مستقل، واتصال SQLite مشترك.
- **لماذا لا يحجز سيرفر RMI القفل أثناء استدعاء SOAP؟** التحقق من الموظف يتم **قبل** أخذ القفل، حتى لا يوقف استدعاء SOAP بطيء باقي العملاء.
- **ما وظيفة RMI Registry؟**
  - دليل أسماء: السيرفر يسجّل الكائن باسم `LibraryService` (`rebind`).
  - العميل يبحث عنه بالاسم (`lookup`) ويحصل على Stub.
- **لماذا Book و Loan تطبق Serializable؟** لأنها تنتقل عبر الشبكة كقيم وتُحوَّل إلى bytes.
- **لماذا Employee يحتاج constructor فارغ؟** JAXB ينشئ الكائن ثم يملأ حقوله من XML عبر الـ setters.
- **كيف تحمي من SQL Injection؟** كل الاستعلامات بـ `PreparedStatement`.
- **كيف تُخزن كلمات المرور؟** PBKDF2-HMAC-SHA256 (210,000 تكرار) مع salt عشوائي لكل مستخدم، ولا تُخزَّن نصاً صريحاً. التكرار الكثير يجعل تخمين كلمة المرور من قاعدة بيانات مسروقة بطيئاً جداً.
- **ماذا يحدث إذا توقف سيرفر SOAP؟**
  - المكتبة تبقى تعمل للقراءة والطلاب.
  - عمليات الموظفين في المكتبة تُرفض برسالة واضحة، لأنه لا يمكن التحقق من الموظف.
  - شريط الحالة يتحول للأحمر.
